# プロジェクト移行の手引き（ガンダムウォー ネット対戦）

キムチ鉄平で作った「新しいプロジェクトの手引き」を元に、この卓をプロジェクトに移すための資料。キムチ鉄平の手引きと違うところは、**中身がもうある**ことと、**公開の仕方がキムチ鉄平と違う**こと（下の「違い」）。

## ナツキがすること（5分ほど）
1. claude.ai で新しいプロジェクトを作る。名前は「ガンダムウォー ネット対戦」
2. **プロジェクト指示欄**に下の「指示欄」を貼る
3. プロジェクトの設定のリポジトリに `natsuki1204s-hash/gundamwar` を足す
4. プロジェクトチャットで下の「メモリー」を貼り、「これをプロジェクトメモリーにそのまま保存して」と頼む
5. 続けて「最初の頼み」を貼る
6. 6501番以降の取り込み（`gundamwar_cards_extra2.json`）が終わっていたら、そのスレッドに添付する

## うまく始まったかの確かめ
最初のスレッドの返事で、めぐみん風の口調・引き継ぎ書の版1・`clone → start.sh → push` が通ったこと・最後の「今回の使用量」の1行が出れば成功。

## 指示欄
```
ガンダムウォー ネット対戦（仲間内でカードゲーム「ガンダムウォー」をブラウザで対戦・観戦する卓）の開発プロジェクト。

始め方：毎スレッド、リポジトリ natsuki1204s-hash/gundamwar をつなぎ（push）、git clone --depth 1 してから bash tools/start.sh で引き継ぎ書（docs/引き継ぎ書.md）と最近の commit を読んでから作業する。start.sh が止められたら手で cat docs/引き継ぎ書.md と git log --oneline -5。引き継ぎ書が作業の状態と決まりの正本。

決まり：
- 1スレッド1話題。終わる前・話題を変える前に引き継ぎ書を今の状態に直して commit・push
- 返事の最後に「今回の使用量」（bash tools/end.sh の1行。道具なしなら「会話のみ」）
- 公開の仕方は引き継ぎ書に従う（仲間はclaude.aiのアカウントなしで遊ぶので、アーティファクトでは公開しない）
- cards.js のカードidは変えない（保存済みデッキが壊れる）
- 口調はめぐみん風
```

1. natsuki1204s-hash/kimchi-teppei の tools/（end.sh・usage.py・check.sh・toc.sh・bump.sh）と docs/公開の手順.md・docs/プロジェクトの指示.md の形を写して gundamwar に置く（中身はガンダムウォー用に直す。start.sh はもうあるので合わせて直す。公開の手順は GitHub Pages 用に書く）
2. 引き継ぎ書を版1にする（版0の中身は残す）
3. clone → start.sh → check.sh → main への push が通るのを確かめる

5. extra2 の取り込み結果を添付していたら、tools/merge_raw.py で取り込んで、色別の番号の穴がいくつ残ったか教えて

## キムチ鉄平の手引きとの違い
1. **公開**：キムチ鉄平は「非公開リポジトリ＋非公開アーティファクト」。この卓は仲間がアカウントなしで開くので**公開リポジトリ＋GitHub Pages**で始めている。手引きのメモリーにある「GitHub Pages は使わない」は、この卓には入れない。どうするかは引き継ぎ書の「未決」
2. **つなぎ方は決定済み**：手引きの「ネット対戦の作り方の案を2〜3出して選ばせる」は不要。PeerJS（ブラウザ同士の直接接続）、部屋を作った人が盤面の管理役、と決めてある
3. **進行と画面を分ける・種つき乱数**（手引き6の9〜11）は、対戦卓を作るときに取り入れる。手動卓なので、送る物は「盤面の操作の列」になる。山札のシャッフルは各自のブラウザでやり、結果は外に出さない
4. **カードはデータに**（手引き6の12）は済み。cards.js が正本、作り直しは tools/merge_raw.py

## 移行前のチャットに残っていて、引き継ぎ書に入れた物
- 決定事項（通信・観戦・画像・デッキ保存・PC前提）
- カードの読み方・デッキ構築ルール（ナツキ確認済み）
- 取り込みの経緯と、残りの穴の場所
- Wiki の生データ（data/raw/wiki_pages.json）。作業場が消えても作り直せる
