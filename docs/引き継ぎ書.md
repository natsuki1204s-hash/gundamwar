# 引き継ぎ書（ガンダムウォー ネット対戦）

版2（2026-11-10、対戦卓の叩き台）

## これは何か
仲間内でカードゲーム「ガンダムウォー」（バンダイ、販売終了）をブラウザで対戦・観戦する卓。カードデータは [GUNDAM WAR Wiki](https://w.atwiki.jp/gundamwar/) から取り込んだ。公開中：https://natsuki1204s-hash.github.io/gundamwar/ （GitHub Pages、main の直下をそのまま公開）

## 進め方
- 始めに `bash tools/start.sh`（止められたら `cat docs/引き継ぎ書.md` と `git log --oneline -5`）
- 返事の最後に `bash tools/end.sh` の1行（この会話のトークン数。同じ requestId は1回だけ数える）。「今の文脈」が50万を超えたら新しいスレッドを勧める
- main へ直接 push、push の前に `git pull --rebase`。大きい作り替えだけブランチ
- 終わる前・話題を変える前にこの引き継ぎ書を今の状態に直して commit・push
- 大きいファイル（cards.js 2.3MB、data/ の JSON）は丸読みしない。`python3 -c` で必要な所だけ引く

## ずっと効く決まり（決定済み）
1. **対戦は手動卓＋少し自動化**。ルール処理は人が口頭で。効果の自動処理はしない。自動化は「ターン開始のリロールとドローをボタン一発」程度
2. **通信はブラウザ同士の直接接続（PeerJS）**。仲間は claude.ai アカウントなしで遊ぶ（アカウントを作らない頑固な仲間がいるため、アーティファクトの共有機能は使えない）。部屋を作った人が部屋コード（例 GW-4821）を出し、他の人は対戦者か観戦者として入る
3. **部屋を作った人のブラウザが盤面の管理役**。手札・山札は各自のブラウザから出さない。観戦者からも手札は見えない
4. **PC前提**。デッキ構築画面だけはスマホでも使える
5. **観戦は最初から入れる**（対戦者の画面から操作ボタンを抜いた読むだけの画面）
6. **画像**：①ブラウザごとの画像（IndexedDB、カード名に紐付け）②サイトの `images/`（`images/index.json` に「番号かカード名 → ファイル名」で登録すると全員に見える）③なければカード風の枠。対戦卓も同じ `cardFace()` を使う
7. **デッキはブラウザ（localStorage）に保存**。端末間はデッキコード（「3 ザクII(スレンダー機) [U-159]」を1行ずつの人が読めるテキスト。LINEで送れる）で運ぶ。同期が欲しくなったら Firebase（登録はオーナーだけで済む）を検討
8. **カードの id は変えない**。`cards.js` の id は「番号|名前」、同じものが重なると「#2」がつき、並び順で決まる。`tools/merge_raw.py` は並び順を保つ。並べ替えると保存済みデッキが別カードを指す
9. 使用量の1行を返事の最後に出す（`tools/end.sh`）
10. 公開は公開リポジトリ＋GitHub Pages（下の「公開の仕方」）

## カードの読み方（ナツキ確認済み）
- `U-159 緑 1-1-1 C` → 番号 / 色 / 指定国力-合計国力-資源コスト / レア度
- `宇宙 地球 [2][0][2]` → 地形適性 / 格闘力・射撃力・耐久力
- 色は 白 青 緑 黒 赤 茶 紫、それと 無色（「無」として扱う）
- 種類：ユニット U・キャラクター CH・コマンド C・オペレーション O・G・ACE

## デッキ構築ルール（Wikiより、ナツキ提示）
- ちょうど50枚
- G以外の同名カードは3枚まで。ユニットは「型番を含む名称」で判定（MS-06S シャア専用ザクII と型番違いは別）
- 基本Gは何枚でも（Wikiにページがないので index.html 側で7色分を用意。id は `BASIC|白` など）
- 特殊Gは合計6枚まで
- 実装：index.html の `RULE_DEFAULT`。画面の「ルール設定」で身内ルールに変えられ、「公式ルールに戻す」もある

- **自動化の段階**：①ダメージの数字を入れて確定 → 本国の上から捨て山へ（すぐ足せる）②戦闘エリアの格闘力・射撃力の合計からダメージ候補、耐久力を超えたユニットの破壊を提案（押すかは人）③カード効果の自動処理は現実的でない（やるならよく使う数枚だけ個別に）。今の「効果の自動処理はしない」の決まりとは①②は食い違わない

- **台本式対戦**（とても複雑なキムテツ）：Claude同士が1試合の操作を台本として書き出し、卓が順番に再生して皆で観戦する。そのために操作は全部 `act({t:...})` の形で管理役の `apply()` を通し、`B.rec` に記録している（「記録を保存」でJSON）。再生機能はまだない

## 取り込みでわかったこと
- Wiki は1カード1ページ。同名の収録違いは同じページに並ぶ。セット一覧（pages/11.html）からはすべてのカードに辿れない
- 新しめのページは型番行が囲み枠（pre）に入っていない書き方がある
- 取り込みは3秒（2回目以降2.5秒）間隔。弾かれたことはない。WebFetch ではセットページ・カードページが弾かれる
